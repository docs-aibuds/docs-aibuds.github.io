All-in-One इंटीग्रेशन

पूरा SDK suite चाहने वाले products के लिए AIBudsSDK/AllInOne सुविधाजनक integration है। एक dependency से Core device support, ABMate connectivity, logging, AI providers और dashboard, on-device voice assistant authentication, crash reporting, live-stream middleware, audio dependencies तथा video stabilization शामिल हो जाते हैं।

Install और initialization code के लिए Installation तथा Quick Start देखें। यह पेज इस विकल्प के architectural प्रभाव समझाता है।

Initialization क्या संभालता है​

AIBudsAllInOneSDK.initialize केवल Core को call forward नहीं करता, बल्कि coordinated setup करता है:

  1. XLFacility logging plugin configure करता है।
  2. StarBurst और MLTCloud device-auth bridges register करता है।
  3. On-device voice assistant authentication bridge register करता है।
  4. Built-in video stabilization plugin register करता है।
  5. AIBudsSDK को ABMateSDK और दिए गए Core configuration/delegate के साथ initialize करता है।
  6. Bundled StarBurst और MLTCloud provider implementations के साथ AIBudsAISDK initialize करता है।
  7. Initialization सफल होने के बाद shared audio-session coordinator शुरू करता है।

Crash Reporter installation और AI Dashboard startup अलग explicit operations रहते हैं। वे dependency में शामिल हैं, लेकिन initialize उन्हें अपने-आप enable नहीं करता।

All-in-One कब चुनें​

  • Product में SDK की अधिकतर feature families चाहिए।
  • Binary size control की तुलना में तेज integration और consistent default plugin set अधिक महत्वपूर्ण है।
  • Bundled AI providers और built-in stabilization implementation product policy के अनुरूप हैं।
  • एक application-level owner global logging और audio-session setup संभाल सकता है।

Modular Integration कब चुनें​

  • Device features का केवल छोटा subset चाहिए।
  • App अपना AI stack या optional media processors देता है।
  • Binary size, third-party transitive dependencies या startup side effects पर कड़ा नियंत्रण चाहिए।
  • App के पास पहले से उन्नत audio-session policy है।
  • Security policy target में diagnostic servers या crash capture की अनुमति नहीं देती।

दोबारा Initialization न करें​

All-in-One सफल होने के बाद AIBudsSDK या AIBudsAISDK अलग से initialize न करें और All-in-One द्वारा चुने plugins के लिए competing implementations register न करें। Feature code को initialized suite उपयोग करना चाहिए, दूसरा global owner नहीं बनाना चाहिए।

Initialization false लौटाए तो feature startup जारी न रखें। Logs देखकर असफल Core या AI stage ठीक करें; public return value यह नहीं बताता कि कौन-सी dependency विफल हुई।

Optional Components के लिए Policy आवश्यक है​

  • Report consent, retention और upload behavior तय करने के बाद ही Crash Reporter जल्दी install करें।
  • AI Dashboard केवल controlled diagnostic builds और networks में शुरू करें।
  • Live Streaming तभी उपयोग करें जब app player/streamer cleanup संभालता हो।
  • Plugin pre-registered होने पर भी stabilization source-file fallback और storage policy बनाए रखें।

अपनाने से पहले जाँच​

  • Product ने हर All-in-One dependency जानबूझकर स्वीकार की है।
  • Initialization application-level owner से केवल एक बार होता है।
  • Initialization से पहले Core configuration और delegate final हैं।
  • Audio-session behavior host app के compatible है।
  • Crash Reporter और AI Dashboard अलग policy gates के अधीन हैं।
  • Core, AI या plugin initialization duplicate नहीं है।
  • भविष्य में modular integration पर जाने के लिए owner और regression plan है।
