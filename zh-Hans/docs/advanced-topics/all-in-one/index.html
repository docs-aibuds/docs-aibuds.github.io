All-in-One 集成

AIBudsSDK/AllInOne 适合需要完整 SDK 套件的产品。只需添加一个依赖，即可引入 Core 设备支持、ABMate 连接、日志、AI 服务商与 Dashboard、离线语音助手鉴权、崩溃报告、直播中间件、音频依赖和视频防抖处理。

安装和初始化代码请参阅安装和快速开始。本页说明选择这种集成方式对架构的影响。

初始化负责的工作​

AIBudsAllInOneSDK.initialize 会执行协调配置，而不是简单地转发给 Core：

  1. 配置 XLFacility 日志插件。
  2. 注册 StarBurst 和 MLTCloud 设备鉴权桥接。
  3. 注册离线语音助手鉴权桥接。
  4. 注册内置视频防抖处理插件。
  5. 初始化 AIBudsSDK，并传入 ABMateSDK、Core 配置和 Delegate。
  6. 使用内置 StarBurst 和 MLTCloud AI 服务商实现初始化 AIBudsAISDK。
  7. 初始化成功后启动共享音频会话协调器。

App 闪退收集器 安装和 AI 服务分析仪表盘 启动仍是显式操作；All-in-One 包含它们，但 initialize 不会自动启用。

适合使用 All-in-One 的情况​

  • 产品计划提供 SDK 的大部分功能。
  • 快速集成和一致的默认插件集比控制二进制体积更重要。
  • 内置 AI 服务商和视频防抖处理符合产品策略。
  • 应用级单一持有者可以接管全局日志和音频会话配置。

应优先选择模块化集成的情况​

  • 只需要少量设备功能。
  • 应用提供自己的 AI 技术栈或可选媒体处理器。
  • 需要严格控制二进制体积、第三方传递依赖或启动副作用。
  • 应用已经具有复杂的音频会话策略。
  • 安全策略不允许某个 Target 包含诊断服务器或崩溃捕获。

避免重复初始化​

All-in-One 成功后，不要单独初始化 AIBudsSDK 或 AIBudsAISDK，也不要为 All-in-One 已选择的插件注册冲突实现。功能代码应使用已经初始化的套件，而不是创建另一个全局持有者。

如果初始化返回 false，不要继续启动功能。请检查日志并修正失败的 Core 或 AI 阶段；公开返回值不会指出具体失败的依赖。

可选组件仍需产品策略​

  • 只有在定义报告授权、保留和上传行为后，才应尽早安装 App 闪退收集器。
  • 仅在受控的诊断构建和网络中启动 AI 服务分析仪表盘。
  • 只有应用能够负责播放器和推流器清理时才使用 Live Streaming。
  • 即使视频防抖处理插件已预先注册，也要保留源文件回退和存储策略。

接入检查清单​

  • 产品明确接受 All-in-One 的全部依赖。
  • 由应用级持有者执行且只执行一次初始化。
  • 初始化前已确定 Core 配置和 Delegate。
  • 音频会话配置与宿主 App 的音频策略兼容。
  • App 闪退收集器 和 AI 服务分析仪表盘 仍由独立产品策略控制。
  • 不存在重复的 Core、AI 或插件初始化。
  • 已为未来切换到模块化集成指定负责人和回归计划。
